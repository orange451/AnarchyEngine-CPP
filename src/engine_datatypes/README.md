# engine_datatypes

Values a property holds and a script passes around: `Vector2` (`Vec2` in C++), `Vector3` (`Vec3`), `Color3` (`Color3`), `Color` (`ColorRgb`), and `Matrix4`. A value has no identity and no place in the tree. `types.hpp` in engine_core includes these headers, so most code gets them without asking.

`Vector3.cpp` also installs the `Vector3` library into a Luau state. A `Vector3` is Luau's built-in vector. `Vector2.cpp` installs `Vector2`, which is a userdata, since Luau has no two-component vector: `typeof` is `Vector2` and the arithmetic operators work on it. `Color3.cpp` installs Roblox's `Color3`, a userdata with `R`, `G`, and `B` from 0 to 1: `new`, `fromRGB`, `fromHSV`, and `fromHex` build one, `Lerp`, `ToHSV`, and `ToHex` read it, and `==` compares it. A `Color` property takes a `Color3` as well as a table, as an opaque color. `Matrix4.cpp` installs `Matrix4`, a userdata over a column-major 4x4 matrix: `new`, `lookAt`, `Angles`, `fromAxisAngle`, and the other constructors build one; `Position`, `LookVector`, `Inverse`, `Lerp`, `ToObjectSpace`, and the rest read it; `*` composes two or moves a `Vector3`, `+` and `-` move it by a `Vector3`, and `==` compares it. A GameObject's `Transform` is a `Matrix4`. The same math is there for C++ as `matrix4_multiply`, `matrix4_inverse`, and the other functions in `Matrix4.hpp`. `Enum.cpp` installs `Enum`: `NormalId`, `Axis`, `RotationOrder`, and the input enums `KeyCode`, `UserInputType`, and `UserInputState`, with Roblox's values. Each item is one userdata, so `==` holds, and a function that takes an enum accepts the item, its name, or its value.

`Curve.cpp` holds `NumberCurve` and `ColorCurve`, the values a particle property varies by. A `NumberCurve` is a `Constant`, a `Range` (a random pick between two numbers, once per use), a `Curve` (keys over time 0 to 1, each `Linear`, `Smooth`, or `Step` to the next), or a `CurveRange` (a random blend of two curves). A `ColorCurve` is the same for a color and its transparency: `Constant`, `RandomBetween`, `Gradient`, or `GradientRange`. Neither caps its keys; `CurveTable` and `ColorTable` bake one into 64 samples, so reading a curve costs the same at any number of keys. Both are immutable. A property holds one in a `LuaSlot` by `shared_ptr`, saved as the JSON in engine_core's `CurveJson.hpp`. `CurveLua.cpp` installs the `NumberCurve` and `ColorCurve` libraries; a script that writes a number to a `NumberCurve` property, or a `Color3` to a `ColorCurve` one, writes a `Constant`.
