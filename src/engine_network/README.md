# engine_network

`engine_network` replicates a server's instance tree to its clients over `anarchy_network`. Spec: `docs/superpowers/specs/2026-10-13-server-client-design.md`.

Bottom up: `ByteBuffer` (`ByteWriter` and `ByteReader`: little-endian values, varints, strings, never reading past the end), `JsonWire` (a property value as a save would write it, in binary; a number takes four bytes when a float holds it exactly and eight otherwise, so every value arrives exactly), `TreeCodec` (the op stream: `StringTable`, `OpWriter`, `read_ops`; codec version 2, named in every snapshot part's header and every Changes message). `RemoteCodec` (`encode_remote`, `decode_remote`: a RemoteEvent's fired payload as `MessageType::Remote`, the remote's NetId, then each argument, nils included, as a tagged value; numbers as JsonWire writes them, engine values as their saved JSON with an Enum's type named, instances as NetIds the caller maps, so one the other side lacks reads nil, and tables as their array part and string keys; decoding checks every length and refuses a table nested past 32 or a message over its cap). `Replicator` (what clients may see, and the join snapshot: the filtered tree as one op stream, zstd-compressed, cut into parts) and `ReplicaApplier` (reassembles a snapshot and applies ops through the ordinary setters, counting refused ones as skipped; a Destroy frees the netid of everything it takes). `Replicator::end_tick` turns each tick's journal into one Changes message. `Sessions` (`ServerSession`, `ClientSession`) wire an `anarchy_network` Endpoint to the tree: the server gives each client a Connection, its snapshot at the end of the tick it connects, and every later tick's changes behind it, one shared buffer for every client, dropping a client whose queue makes no progress for 30 s or grows past 256 MB ("Your connection could not keep up"); the client sets the Client role and starts play while empty, builds the world from the snapshot, and when the connection ends stops play it started, puts back the role it replaced, and says why in words for a player. A script that destroys a client's Connection removes that client ("Removed by the server"), and a closing server tells every client at once ("The server closed"). A connect the endpoint refuses leaves the client Disconnected ("Could not connect to the server"). `ClientSession::status()` copies the state and reason under a mutex for a thread other than the simulation's, such as a window's overlay. A client session runs in one of two modes (`ClientMode`): `FromEmpty` is `--connect` as above, and `Swap` is a script's join, where the playing standalone world stays untouched until the whole snapshot is in; then `ReplicaApplier::before_snapshot` runs `swap_for_client` and the world becomes a Client. A Persistent survivor that its service refuses goes with what held it, and the developer sees why in the script output (`ClientSession::on_warning`). A malformed op after the swap still fails the apply and leaves a half-built world ("Bad data from the server"). A Swap connection that ends never stops play, and puts the role back only if the swap ran. `ClientSession::on_state` tells its owner, on the simulation thread, each time the state or reason changes. `ClientJoinHost` is a client program's `engine_core::IJoinHost`: `join` resolves the address on a thread of its own and hands the answer to a PreAnimation job on the thread stepping the world, dropping it when a Leave, a second Join or the host's end came first; it then connects a Swap session and reports Joined and Left through `Connections`. At most four lookups run at once (`kMaxLookups`); `set_lookup` swaps the resolver for tests. A script's Leave only asks (`ClientSession::request_disconnect`): the connection ends at the session's next receive, between steps, so whatever the end does (`--connect` stops play and closes the play VM) never runs under the calling script. `connect_from_empty` is `--connect` through the same host: it clears the world and makes the session at once, but the connect, and its 5 s timeout, wait for the host's job on the engine's first step, after the window is up. `end_silently` (Studio Stop) ends any connection without Left. `ClientJoinHost::status()` copies the session's state and reason under a mutex for another thread (the player's overlay); it is Idle while there is no session. Given the resources folder in place of a whole identity (`project_identity_unhashed`), the host hashes it only when the first join (on its resolver thread) or connect needs it, so a program that never joins never reads every resource file; `set_before_hash` runs just before (a packed player makes its empty resources folder again there). AnarchyPlayer makes one host before its engine starts and takes it down after the engine stops; `--connect` goes through `connect_from_empty`, and only `--connect` shows the "Connecting…" overlay, since a game that joins from a script draws its own loading screen. Studio makes one per test inside the edit that starts play (paused, under the write lock, so binding its job is safe), and Stop, in the edit that stops play, first stops play (so the role going back starts no Server script), then ends the connection silently, uninstalls and destroys the host, and runs `clear_connections`, since the restored place never held the server's Connections. AnarchyServer installs none. A session that ends inside its own callback is unhooked at once and destroyed at the next tick. `ClientWorld` (`clear_for_client`, `swap_for_client`, `clear_connections`) empties a client's world down to its services, each back at its defaults, before it connects, so the snapshot builds the place into nothing else (a snapshot carries only the service values that differ from the defaults). `ProjectIdentity` (`project_identity`) is the `GameIdentity` a project presents, refusing a missing or all-zero gameId and an unreadable resources folder with a reason for a person. A session's now is `engine_core::Engine::network_now()`, the clock the engine pumps it with. Both sessions are their world's `engine_core::IRemoteSink` while they live. A server's `FireClient`, `FireClientExt` and `FireClientAll` encode the message once (an instance clients do not see reads nil; over 262144 bytes raises on the sender), and `send` queues it to each target after that tick's Changes, through the same per-client queue, so an instance created in the tick is on the client first; a client whose snapshot is not queued yet gets it right after the snapshot. A client's `FireServer` names instances by the server's netids (its own read nil) and goes out at the next send, in firing order. The server now reads what clients send: a RemoteEvent message fires `OnServerEvent` with the sender's Connection only from a joined client, for a live replicated RemoteEvent, decoded within 262144 bytes, and within `SessionConfig::max_remote_bytes_per_pass` (4 MiB) of that client's accepted bytes in one receive; anything else is dropped and counted in `dropped_remotes()`, never a kick. Other client messages still count in `dropped_messages()`. A client holds a server message for a remote no script listens to yet (up to `kMaxUnheardRemoteBytes`, 4 MiB) and fires it at the next receive after one connects, since a script that arrives in the snapshot connects after the messages behind it. `Sessions.hpp` lists the rules a session's owner keeps.

Nothing in the engine packages includes this library: `Engine` reaches a session only through `engine_core::INetworkPump`.
