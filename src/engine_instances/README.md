# engine_instances

The instance classes: `GameObject`, `Camera`, `Folder`, `Script`, `ModuleScript`, `PhysicsBase` and its `PhysicsObject` and `PlayerController`, `Attachment`, `SoundEmitter`, `Skybox`, `DynamicSky`, `BloomEffect`, `ScreenSpaceReflections`, `AmbientOcclusionEffect`, `Terrain` and `TerrainMaterial`, the GUI classes, and the six asset classes. Each inherits `DataModel` from engine_core and registers its Lua class, with any properties, in its own `.cpp`.

The asset classes live in `AssetInstances.{hpp,cpp}`, each only under its own category in `Assets`. `Texture`, `Mesh`, and `Sound` are a `FileAsset`, with a `Path`. `Material` and `Model` are a `ReferenceAsset`, whose saved properties are references held by GUID (`InstanceRef`, from engine_core): `Material` has `DiffuseTexture`, `NormalTexture`, `RoughnessTexture`, `MetalnessTexture`, and `EmissiveTexture`, each a `Texture?`, plus `Color` (a `Color3`, white) and `Reflectivity` (0.5) and `Transparency` (0), numbers shown on a 0 to 1 slider; `Model` has `Mesh` and `Material`. `Prefab` holds `Model`s as its only children.

`Camera` is a `GameObject` with a `FieldOfView`, in degrees from 1 to 120, a saved registry property. Its Transform places it, looking down its -Z. A new place starts with one in Workspace (`Project::add_default_camera`), and each Scene View follows one Camera in Workspace, chosen from the list at its top right; the render snapshot carries the Camera's FieldOfView on its row.

`PhysicsBase` (`PhysicsBase.hpp`) is the abstract base of every rigid body, `PhysicsObject` and `PlayerController`: a `PVInstance` with its own Transform, not a GameObject, holding Transform, Velocity, Anchored, Mass, LinearDamping, and GameObject. Its class says `physics_body()`, which tags its entity so `PhysicsWorld` (engine_core, the only code that includes Box3D) finds the ones in Workspace. Script and Properties writes mark what changed in a dirty mask the physics world takes each step; the world's own writes go through `store_simulated` and record nothing. `PhysicsObject` adds its Shape, Size, and material. `Shape` is the first enum-typed saved property (`lua_saved_enum`), saved as the item's name, and `Mesh` is shown only for a Hull or a Custom (`lua_shown_when`, which takes a set of items).

`PlayerController` is an upright cylinder with no contact friction. `PhysicsWorld` hovers it its hover gap (StepHeight, capped by Height) above the ground its probe finds, and slows it there by its own `Friction`. Its `OnGround` and `IsSliding` are read-only, unsaved fields the world writes through `store_ground`; any Transform written to it keeps only its turn about Y.

`PVInstance` (`PVInstance.hpp`) is the abstract base of every class with a Transform: `GameObject`, `PhysicsObject`, `PlayerController`, and `Attachment` inherit it, each keeping its Transform its own way behind the virtual `transform()`. It has no source file, so `GameObject.cpp` registers its Lua class.

`Attachment` keeps only its `Offset` and `OffsetSpace`, saved registry properties; `transform()` multiplies the parent's frame by Offset on each read (`parent_frame()`: the parent's Transform in Local, its position alone in World), and `set_transform` solves for the Offset. `on_parent_changed` fires Changed for `Transform` when the new parent moves it. `Enum.TransformSpace` (World 0, Local 1) is shared with `Dragger.Space`.

`SoundEmitter` plays its `Sound` reference. Its class says `sound_source()`, which tags its entity so `AudioWorld` (engine_core, the only code that includes miniaudio) finds the ones under game each frame. `Play` and `Stop` are bound in `ScriptBindings`. Setters mark a dirty mask the audio world takes each step; the world's own writes (TimePosition as the sound plays, IsPlaying at its end) go through `store_playback` and record nothing. Its `read_place` stops it, so Stop never leaves one playing into the next Test.

`Terrain` is a `PVInstance` holding an island of voxels: a `terrain::VoxelVolume` (engine_core's `terrain/`) in Terrain-local space, placed by its saved `Transform`, which may move and turn it but is refused with any scale or shear ("Terrain cannot be scaled"). `VoxelSize` is read-only and always 1, `CanCollide` is saved, and `DataPath`, the island's `.avox` file, is a hidden saved property (`lua_hidden`). Its `TerrainMaterial` children say what each voxel Id draws and collides as; `add_material` makes one on `free_id()`, the lowest Id no child holds, and refuses past 255.

A Terrain in Workspace is meshed and collides through engine_core's `TerrainWorld`, which the Engine updates every tick, stopped or playing. It sends each chunk an edit touched, and its neighbors, to `TerrainMesher`'s worker threads, which run `surface_nets` and build the chunk's Box3D mesh there, off the simulation thread. The Terrain gets one static body with one mesh shape per chunk that has a surface; `CanCollide` false keeps the body and drops its shapes. `workspace:Raycast` on terrain returns the Terrain as its Instance and the hit voxel Id's `TerrainMaterial` Material as its Material. Each chunk draws in its voxels' Materials' colors. An edit shows, and collides, a frame or two after it is made; until then the chunk keeps its old mesh and shape. Terrain far from the camera draws a simplified LOD mesh instead of every chunk's full detail, so a large island still shows whole at a glance. Colliders exist only around chunks a moving body is actually near, not the whole island; `workspace:Raycast` still hits the terrain's surface at any distance, even where it has no collider, by marching the voxels directly.

`TerrainMaterial` names one voxel Id (`Id`, 1 to 255, saved but read-only to scripts) and its `Material`. It has no Explorer row (`hidden_in_explorer`), keeps the Terrain it was first given (`parent_locked`), may live only in a Terrain (`Containment`), and is made by paste but not by `Instance.new` (`register_lua_creatable(..., false)`). Every path that brings one into a Terrain (load, paste, undo of a delete) sets its Id before its parent, so `on_parent_changed` is where Ids stay unique: whoever already holds an Id keeps it, and an arrival on 0 or a held Id takes the Terrain's lowest free one, as an unrecorded edit. Deleting one leaves its voxels on its Id, drawing as the default, for the next one added to take.

`Script` and `ModuleScript` are separate classes that share `LuaSource`, which holds `Source` and the editor's Edit action. `Script` adds `Enabled` and the start generation the runtime checks; `ModuleScript` adds only its starter source.

A registration runs only if its object file is linked, and that happens only when something uses the class. The `Instance.new` factories in `ScriptRuntime` keep the classes a script can make linked.

The GUI classes live in `Gui.{hpp,cpp}`: `ScreenGui`, `BillboardGui`, `Pane`, `ImagePane`, `HBox`, `VBox`, `Label`, `Button`, and `TextField`, each a `GuiBase` (the Panes through `GuiBasePane`), and `CSS` (`Css` in C++), a stylesheet for its parent, or, when directly under the Gui service, for the whole GUI layer: every ScreenGui and every drawn BillboardGui. They share `GuiValues`, which keeps every property as the `LuaSlot` a script reads, indexed by `GuiProperty`, and checks each write against one table of names, types, and ranges, so a class only lists which properties it registers. `revision()` moves on every change, which is how `runner::GuiLayer` knows a node to update. A GuiBase's events (`MouseClicked` and the rest, and `Action`) are `lua_event` fields, fired with `DataModel::fire_event`. A `BillboardGui` is drawn in the 3D world at its anchor (`anchor()`: `Adornee`, else a PVInstance parent, else the origin) while `drawn()`: in Workspace or Core and not inside another GUI.
