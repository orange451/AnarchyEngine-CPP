# Custom shaders in Unreal, Unity, and Godot

2026-10-20 · Survey for the custom-shader design (`docs/superpowers/specs/2026-10-20-custom-shaders-design.md`). Three web surveys, condensed to the mechanisms and the lessons. Sources are linked at the end of each section.

## Summary

All three engines converge on the same shape, arrived at from different directions:

1. **The user fills in slots; the engine owns the passes.** Unreal's material graph lands in fixed functions of one HLSL template (`GetMaterialBaseColor` and friends) that every pass shader calls. Unity's old surface shaders took one `surf()` function and generated the lit, shadowed, lightmapped passes from it. Godot's `fragment()` writes `ALBEDO`, `ROUGHNESS`, `EMISSION` and the template does the rest. Users love this model wherever it exists, and Unity's biggest shader complaint is that its new pipelines lost it and never got it back (Block Shaders was put on hold in January 2026 after three years).
2. **The shader is the schema; the material is a bag of values.** Unity's `Properties` block, Godot's `uniform` hints, and Unreal's `*Parameter` nodes all generate the inspector automatically and store values by name. Values change without recompiling; only structural switches (Unreal static switches, Unity keywords) make new shader variants.
3. **Post effects are "a full-screen material at a named point in the chain, declaring which buffers it reads".** Unreal's Blendable Location, Unity's Full Screen Pass injection point plus Requirements flags, Godot's Compositor callbacks. Reading the GBuffer is a post-process-only privilege in Unreal; Godot cannot offer it at all (forward renderer).
4. **Variant explosion and first-draw stutter are the universal complaint.** Unreal's vertex-factory × pass × static-switch matrix, Unity's keyword product, Godot's dozens of variants per shader plus driver pipelines. Every engine has spent releases on caches, stripping, and warm-up. An engine with one renderer and a few hand-picked variants per shader avoids most of this by construction.
5. **Error handling that never breaks the scene.** Unity draws magenta on failure and cyan while compiling; Godot reports `error(line)` as you type and keeps the old shader; Unreal needs `r.ShaderDevelopmentMode` to make failures retryable. Godot's is the one users praise.

## Unreal Engine 5

### Material Editor

A material is a node graph whose wires end at one main node with pins for Base Color, Metallic, Specular, Roughness, Emissive, Opacity, Opacity Mask, Normal, World Position Offset, Ambient Occlusion, Refraction, Pixel Depth Offset, Custom Data 0/1, Customized UV0 to 7, and more. Which pins are live depends on three settings: **Material Domain** (Surface, Deferred Decal, Light Function, Volume, Post Process, User Interface), **Blend Mode** (Opaque, Masked, Translucent, Additive, Modulate, AlphaComposite, AlphaHoldout), and **Shading Model** (Default Lit, Unlit, Subsurface, Clear Coat, Two Sided Foliage, Hair, Cloth, Eye, Thin Translucent, and "From Material Expression", which lets a node pick the model per pixel and writes the id into the GBuffer).

The graph is not interpreted. `FHLSLMaterialTranslator` emits one HLSL local per node, then substitutes the chunks into `MaterialTemplate.ush`, producing fixed-signature functions: `CalcPixelMaterialInputs` fills the inputs, `GetMaterialBaseColor(PixelMaterialInputs)` and friends read them, `GetMaterialWorldPositionOffset` is the vertex side. Every pass shader (base pass, depth, shadow, velocity, light function) is written once against those accessors, so one graph serves every pass and every mesh type. Nodes feeding World Position Offset or Customized UVs run in the vertex stage; a `VertexInterpolator` node moves work there explicitly. The generated HLSL is viewable in the editor.

**The Custom node** takes raw HLSL, typed named inputs, an output type, and (since 4.26) extra outputs; the text is pasted into a generated `CustomExpressionN(FMaterialPixelParameters Parameters, ...)` function. Limits that users resent: it is a black box to the translator (no folding across it), HLSL forbids nested functions so helpers need an included `.ush` from the project's `Shaders/` folder, parameters and textures are visible only when wired in, errors point at the generated file, and the node is missing in UEFN. Community plugins (HLSLMaterial) exist purely to let people write `.hlsl` files in an IDE with hot reload.

**Material Functions** are inlined sub-graphs with typed inputs and a palette entry. **Material Instances** override only `*Parameter` nodes: scalar, vector, and texture parameters are uniform values and change with no recompile; **static** parameters (Static Switch, Static Component Mask) are compile-time and every distinct combination is a new shader map. A **Material Instance Dynamic** is made at runtime and breaks auto-instancing because each one is its own render proxy. **Material Parameter Collections** are the global uniforms: assets of up to 1024 scalars and 1024 vectors in one uniform buffer, at most two per material, set from Blueprint for weather and time of day.

### Post Process Materials

Domain = Post Process. Only Emissive Color (the result) and Opacity (blend weight) are used. **Blendable Location** picks the insertion point: Scene Color Before DOF, Scene Color After DOF, Translucency After DOF, SSR Input, Scene Color Before Bloom (HDR, after TAA), Replacing the Tonemapper, Scene Color After Tonemapping (LDR, the default and cheapest). The **SceneTexture** node reads PostProcessInput0 to 6, SceneColor, SceneDepth, CustomDepth, CustomStencil, Velocity, and the GBuffer channels (BaseColor, WorldNormal, Metallic, Roughness, ShadingModelID, AmbientOcclusion, and so on). GBuffer reads are allowed only in the Post Process domain; surface translucency can read only SceneColor and SceneDepth. "Blend with the previous result" is done in the shader by reading PostProcessInput0. Materials attach through a `WeightedBlendables` array on a PostProcessVolume, a CameraComponent, or the PlayerCameraManager, each with a weight; ordering is by Blendable Priority then array order; overlapping volumes interpolate instance parameters, so neutral defaults matter.

### The lower level

Global shaders (`FGlobalShader`, one instance per type, used for full-screen work) versus material shaders, which are templated by material × **vertex factory** (local mesh, GPU skin, landscape, Niagara sprite and ribbon) × pass × quality × platform × static permutation. Which vertex factories a material compiles for is set by usage flags, which the editor sets automatically when the material is applied to something, a classic source of accidental explosion. Mitigations: usage flags, `ShouldCompilePermutation`, the Shader Permutation Reduction project settings, quality switches, and from 5.2 PSO precaching. Compilation runs in ShaderCompileWorker processes and lands in the Derived Data Cache keyed by every input. Hot reload is `recompileshaders changed` (Ctrl+Shift+.). Editing a widely included `.ush` recompiles thousands of materials. Adding a pass or a vertex factory needs C++: `IMPLEMENT_GLOBAL_SHADER`, a plugin shader directory mapping, and a Scene View Extension with `SubscribeToPostProcessingPass` for render-graph insertion. Substrate (default from 5.7) replaces the shading-model enum with a graph of slabs and a per-pixel closure budget.

### Per-object data

**Custom Primitive Data**: 32 floats on every primitive component, read by a parameter node flagged "Use Custom Primitive Data" with an index, so objects share one material and keep auto-instancing (the docs' example: 25 spheres, 94 draws with instances versus 46 with CPD). **Per-instance custom data** on instanced static meshes: N floats per instance, vertex-stage only. **Vertex color**, including per-component overrides from mesh paint.

### What users say

Complaints: compile waits, invisible permutation drivers, PSO stutter on DX12 and Vulkan, the Custom node's black box and awkward includes, no way to author a whole surface or add a pass without C++, and the graph being too technical for simple artist tasks. Praise: the instance workflow (override without recompiling, live viewport), Material Functions as a library, one graph serving every pass and mesh type, and the breadth of scene-texture access.

## Unity (URP, with Built-in and HDRP where they differ)

### ShaderLab

A `.shader` file is `Shader "Path/Name" { Properties {...} SubShader {...} Fallback "..." }`. The **Properties** block is the schema: `_Name("Display", Type) = default` with types Integer, Float, Range(min, max) (a slider), Color, Vector, 2D, 2DArray, 3D, Cube; texture defaults are the named built-ins "white", "black", "gray", "bump". Bracket attributes drive the inspector and keywords: `[HDR]`, `[Normal]`, `[NoScaleOffset]`, `[HideInInspector]`, `[MainTexture]`, `[Toggle]` (a checkbox that also enables keyword `NAME_ON`), `[KeywordEnum(A,B,C)]`, `[Enum(...)]` (commonly feeding `Blend [_SrcBlend] [_DstBlend]`), `[Header]`, `[Space]`. A custom `MaterialPropertyDrawer` class is referenced by the same syntax, and `CustomEditor` takes over the whole inspector (URP's Lit uses it for Surface Type and Blend Mode). The material inspector is generated entirely from the declarations; a `.mat` is YAML holding the shader GUID, keywords, a render queue override, and `m_SavedProperties` by name, so a material keeps stale entries when its shader changes.

**SubShader tags** gate pipeline compatibility (`"RenderPipeline"="UniversalPipeline"`), queue, and RenderType. **Pass tags** name the slot a pass fills: `UniversalForward`, `UniversalGBuffer`, `DepthOnly`, `DepthNormals`, `ShadowCaster`, `Meta`, `MotionVectors`. Render state (Blend, ZWrite, Cull, Stencil) lives outside the HLSL and can reference properties. **Render queue**: Background 1000, Geometry 2000, AlphaTest 2450, Transparent 3000, Overlay 4000; up to 2500 sorts front to back, above it back to front.

**MaterialPropertyBlock** overrides values per renderer without a material copy but cannot change render state and drops the renderer off the SRP Batcher's fast path, so URP users are pushed toward instancing or material variants.

### Variants and keywords

`#pragma multi_compile A B` builds every combination; `#pragma shader_feature` builds only the combinations materials in the build use, so a `shader_feature` keyword cannot be switched on at runtime unless some built material used it, and a stripped variant is silently replaced with "a similar one". The manual's example: 10 two-keyword sets = 1024 variants per pass per API. Mitigations: `_local` keywords, per-stage suffixes, `#pragma dynamic_branch` (one program, a uniform `if`), stripping in Graphics Settings and `IPreprocessShaders`, and warm-up through Shader Variant Collections and Unity 6's `GraphicsStateCollection`, because DX12, Vulkan, and Metal need the whole pipeline state to prewarm accurately.

### Shader Graph

A JSON asset that the importer turns into a full ShaderLab shader. The **Master Stack** has a Vertex context (Position, Normal, Tangent) and a Fragment context whose blocks depend on the target: URP Lit shows Base Color, Normal, Metallic, Smoothness, Emission, Occlusion, Alpha, Alpha Clip Threshold; Unlit shows Base Color and Alpha; Fullscreen shows Base Color, Alpha, and depth outputs with no vertex blocks. Each target fills its own pass templates (ForwardLit, GBuffer, ShadowCaster, DepthOnly, DepthNormals, Meta, MotionVectors) from the graph's functions, so the user never writes passes, and vertex displacement flows through the Position block so every pass agrees. The **Custom Function** node takes a string body or an `.hlsl` file and typed ports; it cannot add passes or change render state, and previews lack the pipeline includes. Sub Graphs package reusable nodes. Keywords (Boolean or Enum, Shader Feature or Multi Compile) compile to `#if` and can generate a `[Toggle]` material property.

### Post-processing

The **Volume** system: a Volume (global, or local with a collider, with weight, priority, and blend distance) holds a Volume Profile of `VolumeComponent` overrides; each frame the stack is interpolated by priority and distance. A custom effect is a `VolumeComponent` with typed parameters. The **Full Screen Pass Renderer Feature** is the low-code route: a material, an injection point (Before Transparents, Before Post Processing, After Post Processing), and **Requirements** flags (Depth, Normal, Color, Motion) that force the matching prepass or copy (`_CameraDepthTexture`, `_CameraNormalsTexture`, `_CameraOpaqueTexture`). The code route is a `ScriptableRendererFeature` enqueuing a `ScriptableRenderPass` at one of 18 `RenderPassEvent`s, in Unity 6 through `RecordRenderGraph` with `UniversalResourceData` exposing the active color and depth, the opaque copy, normals, motion vectors, and the GBuffer. HDRP has Custom Pass Volumes (injection points that document which buffers are readable where) and Custom Post Process components that must be listed in a project-wide order.

### Surface shaders and the gap

Built-in only: `#pragma surface surf Standard` plus `void surf(Input IN, inout SurfaceOutputStandard o)` filling Albedo, Normal, Emission, Metallic, Smoothness, Occlusion, Alpha. The compiler derived the interpolators and emitted ForwardBase, ForwardAdd, Deferred, ShadowCaster, and Meta passes with every lighting keyword set. Loved because one function gave a fully lit, shadowed shader that survived engine updates. URP and HDRP never had it: a hand-written lit URP shader needs five to seven passes and long `multi_compile` lists copied from `Lit.shader`, and the library headers are "not really designed to define a public/private API contract" (Unity staff), so they break between versions. The replacement, Block Shaders, was demoed in October 2022 and put on hold on 28 January 2026.

### Iteration loop

Saving a shader reimports and recompiles dependents; the editor compiles variants on demand into `Library/ShaderCache`. Asynchronous compilation draws **cyan** while compiling; compile failure draws **magenta** and logs file:line to the Console and the shader inspector, which also offers "Compile and show code". `Shader.PropertyToID` turns a name into a session-stable int.

## Godot 4.x

Godot is the closest model to what we want: one small text language, no graph required, hints that make the inspector, and errors as you type.

### The language

One file: `shader_type spatial;` (or `canvas_item`, `particles`, `sky`, `fog`), an optional `render_mode a, b;` line, then uniforms, varyings, functions, and the processor functions the user chooses to fill in: `vertex()`, `fragment()`, `light()` for spatial. Anything left out gets the engine default, and any output never written is compiled out. GLSL ES 3.0 flavored, with restrictions (floats need a decimal point, uniforms get defaults).

`fragment()` writes `ALBEDO`, `ALPHA`, `METALLIC`, `SPECULAR`, `ROUGHNESS`, `EMISSION`, `NORMAL_MAP`, `AO`, `RIM`, `CLEARCOAT`, `DEPTH`, `FOG`, and reads `FRAGCOORD`, `FRONT_FACING`, `VIEW`, `UV`, `UV2`, `COLOR`, `VERTEX` (view space), `SCREEN_UV`, plus globals `TIME`, `VIEWPORT_SIZE`, `CAMERA_POSITION_WORLD`, the matrices, `INSTANCE_ID`. `vertex()` reads and writes `VERTEX`, `NORMAL`, `UV`, `COLOR`, and may write `POSITION` to bypass projection. `light()` runs once per light with `LIGHT`, `LIGHT_COLOR`, `ATTENUATION`, and accumulates `DIFFUSE_LIGHT` and `SPECULAR_LIGHT`; defining it replaces the stock Burley/GGX model. Writing `ALPHA` silently moves the material to the transparent pipeline; `discard` defeats the depth prepass.

`render_mode` flags: blend (`blend_mix`, `blend_add`, `blend_sub`, `blend_mul`, `blend_premul_alpha`), depth (`depth_draw_opaque`, `depth_draw_always`, `depth_draw_never`, `depth_prepass_alpha`, `depth_test_disabled`), cull (`cull_back`, `cull_front`, `cull_disabled`), shading (`unshaded`, `diffuse_*`, `specular_*`, `vertex_lighting`, `shadows_disabled`, `ambient_light_disabled`, `fog_disabled`), transform (`skip_vertex_transform`, `world_vertex_coords`), and since 4.5 stencil modes. Each becomes a `#define` or an integer the backend reads for pipeline state.

**Uniform hints** are the whole inspector story: `uniform vec4 tint : source_color = vec4(1);` gives a color picker (and sRGB decoding for a sampler), `hint_range(0, 1, 0.1)` a slider, `hint_enum("A", "B")` a dropdown on an int, `hint_default_white` / `hint_default_black` / `hint_normal` / `hint_roughness_r` set a sampler's fallback and semantics, `filter_nearest` / `filter_linear_mipmap` / `repeat_enable` set per-uniform sampling, and `hint_screen_texture` / `hint_depth_texture` / `hint_normal_roughness_texture` bind the engine's own buffers. `group_uniforms Name;` folds the following uniforms under an inspector header. `instance uniform` lives on the node, not the material (16 scalar or vector slots, no textures), so many nodes share one material; `global uniform` is a project-registered value set through `RenderingServer`. `#include "x.gdshaderinc"`, `#define`, and `#if` work as expected.

### Attachment and parameters

`Shader` is a resource holding the text; `ShaderMaterial` holds a shader and a parameter cache; many materials share one shader. In 3D a material attaches per mesh surface, through `surface_material_override`, or through `material_override` on the instance. `next_pass` draws the object again with another material (the only multi-pass), and `render_priority` sorts within the opaque or transparent queue. Script: `set_shader_parameter("name", value)`. Right-clicking a StandardMaterial3D offers **Convert to ShaderMaterial**, which hands the user the gdshader text the built-in material is generated from.

### How it compiles

`ShaderLanguage` parses the text into an AST, validating identifiers against per-type tables. `ShaderCompiler` emits GLSL chunks (uniform block, globals, per-stage code) and a set of flags: which outputs were written, which built-ins were used, which hints were seen. The backend configures renames (`ALBEDO` to `albedo_highp`, `TIME` to `global_time`), usage defines (`NORMAL` touched emits `#define NORMAL_USED`), and render-mode defines, then splices the chunks into its own GLSL template at `#CODE : VERTEX` / `#CODE : FRAGMENT` / `#CODE : LIGHT` markers. User identifiers are prefixed, uniforms packed std140 into one material UBO, and `texture()` calls on Vulkan are rewritten to use a sampler picked from the filter and repeat hints. "Unused outputs vanish" and "writing ALPHA means transparent" are the backend reading those flags, not magic. StandardMaterial3D itself is a generator of this same text keyed by a feature bitmask, which is why conversion is free. Each shader expands into many variants (depth, depth plus normal-roughness, color × ubershader × motion vectors × multiview) cached on disk by hash; 4.4 added ubershaders and background pipeline compilation to fight first-sight stutter.

### Post-processing

Four routes, each with limits: (a) a ColorRect with a canvas_item shader reading `hint_screen_texture`, color only, after every built-in effect; (b) a full-screen quad MeshInstance3D with a spatial shader reading depth and normal-roughness, which is a transparent-pass object, sees only opaques, and runs before glow and tonemap; (c) since 4.3 a `CompositorEffect` with `_render_callback` at pre-opaque, post-opaque, post-sky, pre-transparent, or post-transparent, dispatching raw RenderingDevice compute shaders, powerful but manual and experimental; (d) the Environment's fixed effects (tonemap, glow, SSAO, SSIL, SSR, fog, DOF, adjustments) with no user hooks. Users complained for years that (a) and (b) were hacks, and (c) still requires compute.

### What users say

Praise: the fill-in-`fragment()` model with defaults for everything else, hints producing inspector UI with zero boilerplate, errors with line numbers as you type, conversion of the built-in material as a learning tool, one language across 2D, 3D, particles, sky, and fog. Complaints: multi-pass only through `next_pass`, post-processing before 4.3, no GBuffer (forward renderer), variant and pipeline stutter, `set_shader_parameter` type mismatches failing silently, instance uniforms that cannot be textures.

## Lessons for our engine

- **Give users the surface function.** It is the thing every engine's users ask for and the thing a deferred renderer with one `readSurface()` can offer almost for free. Our `surface.glsl` is already that template.
- **Hints make the UI.** A uniform declaration with a hint is enough to put a slider, a color picker, or a texture picker in the Properties panel. No second schema, no graph.
- **Values are properties, structure is a recompile.** Changing a number or a texture should never recompile. Only the source text does.
- **Keep variants to a handful per shader.** One renderer, one vertex layout, and three passes (G-buffer, see-through, shadow) means a custom shader costs three programs, not a matrix.
- **Never break the scene.** A shader that fails to compile should draw as the plain Material and put its error, with a line number, where script errors already go. Godot's as-you-type reporting is the bar.
- **Post effects are a material at a named point, declaring what they read.** Two points (before and after the tone map), with depth, normals, albedo, and the scene color available, cover almost everything users build.
- **Per-instance values are a later layer.** Unreal's Custom Primitive Data and Godot's instance uniforms exist so that one material can serve many objects without copies. Our instance tint already does this for color; a general version can come after the material-level feature.
