# network

`anarchy_network` moves bytes between a server and its clients over UDP and knows nothing about instances or physics. Spec: `docs/superpowers/specs/2026-10-12-network-transport-design.md`; roadmap: `docs/superpowers/specs/2026-10-12-networking-roadmap-design.md`.

Bottom up: `Bits` (bit packing, quantization), `Sequence` (wrap-aware 16-bit sequence math), `Packet` (the header and the encode/decode hook), `PacketRing` (sent and received rings, acks, RTT, loss), `Socket` (`ISocket`, `UdpSocket`, `LinkHub` for tests), `Conditioner` (latency, jitter, loss, duplication, cap), `ReliableChannel`, `FlowControl`, `Connection` (one peer), `GameIdentity` (game id, version, resources hash), `Endpoint` (server or client).

No threads: every pump call takes `double now` in seconds. No heap use on the packet path; reliable blocks and the conditioner's queue are the exceptions. A reliable block can be handed over as a shared buffer (`SharedMessage`), so one message goes to many peers without a copy each.

A tick's first packet to a peer, when one is due, carries the payload, reliable data, and acks, whatever the budget. While reliable data is still due, more packets follow in the same tick: each spends its length from a byte credit that refills at the flow-controlled rate (`EndpointConfig::bytes_per_second`, halved on loss over 10% or RTT over 250 ms) and holds between minus and plus two ticks' worth. When data is due a peer always sends that first packet, so the effective floor is one packet a tick, about 72 KB/s at 60 Hz, whatever the budget. A tick carries at most `kMaxPacketsInFlight` (128) packets per round trip, between 1 and 32 a tick, judged by the larger of the smoothed RTT and the latest sample. The rings remember 1024 packets each way, eight round trips at that cap, so every ack names a live slot and the loss estimate sees enough packets older than 2 x RTT. Each ack carries 128 bits, four ticks of full bursts, so a few lost acks cost nothing. Flow control is updated once a tick. A peer that heard a payload or reliable data since its last send acks on its next tick. Sessions default to 1 MB/s per client (`engine_network::kDefaultSendBudget`); a bare `Endpoint` to 32 000 bytes/s.

A Disconnect packet ends with one byte saying why: `LeaveCode::Left`, `Closed` (the side shut down, as `Endpoint::close` does for every peer), `Removed` (the server removed this peer), or `FellBehind` (the server dropped this peer for falling too far behind). The receiver reports `Requested`, `Closed`, `Removed`, or `FellBehind`; a packet with no byte, or an unknown byte, reads as `Requested`. A callback may throw: the exception leaves the pump, and a drop it asked for is still made. `resolve("host:port")` takes a literal or looks a name up, preferring an IPv4 answer. `UdpSocket::open` falls back to an IPv4-only socket (`open_ipv4`) when the host cannot make a dual-stack one; that socket cannot reach IPv6 peers.

Tests: `sandbox/network_*_tests.cpp`, tag `[network]`.
